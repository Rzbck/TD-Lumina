# Video review — 2026-09-30 07:48:21

Source reviewed: 56-second TouchDesigner screen recording supplied by the user.

This note records **observations from the video** plus explicit user feedback. It is not a specification by itself; implementation requirements live in `docs/GENERATIVE_SYSTEMS.md` and `docs/VISUAL_LANGUAGE.md`.

## What is working better

- The V8.6.x base is visibly more coherent than the earlier random-flash iterations.
- Real structural frames/rectangles are readable at several moments.
- The arch topology is recognizable instead of becoming a generic particle visualizer.
- Sparse autonomous light points are present and can work as a second layer.

## Problems visible in this recording

### 1. Frames are too synchronized

Several structural frames/rectangles appear to share the same timing language: they build/hold/fade together or at very similar rates. This makes several independent objects read as one block.

Required correction:

- each frame gets an independent phase offset;
- different edge speeds;
- different construction direction;
- independent hold/fade duration;
- all may still belong to the same BPM/bar phrase.

### 2. Repeated regions / repeated silhouettes

The same or very similar rectangular/upright regions recur through the 56-second sample. The viewer can predict the next shape too quickly.

Required correction:

- move source regions;
- change width/height of structural objects;
- rotate through ceiling / left side / right side / cross-arch constructions;
- vary construction style before changing the whole grammar.

### 3. Some structural objects still read as blocks

When several edges are present together, the result can read as a rigid pre-lit frame rather than a living construction.

Required correction:

- draw perimeter progressively;
- allow one edge at a time;
- center-out and corner-start variants;
- optional no-trail mode;
- completed frame may hold, but construction itself should be readable.

### 4. Mobile pixels are too weak relative to geometry

Small points exist, but geometry often dominates them. They do not yet feel like a strong autonomous population moving through the tunnel.

Required correction:

- stronger visibility of individual heads;
- longer individual journeys in some phases;
- independent spawn clocks;
- reduce flock/group behavior;
- music affinity per agent.

### 5. Darkness is still frequent

The sample contains long dark intervals where only a few tiny points remain visible. For this tunnel installation, near-black should be an intentional rare effect, not the default between events.

Required correction:

- maintain a restrained architectural floor while music is present;
- allow black only for explicit sparse/blackout grammar or genuine silence;
- do not solve this with global volume brightness pumping.

### 6. Symmetry must be a full-state rule

The user explicitly rejects a symmetric frame with an unrelated asymmetric event layered on top.

Required correction:

- symmetry state controls primary geometry, secondary geometry, autonomous pixel policy and feedback/trails;
- when pathway/lightning takes over, symmetry turns OFF cleanly.

## Choreography requested after this review

A particularly strong target sequence is:

1. construct **Portal A** asynchronously;
2. hold it briefly;
3. launch one slow lightning/pathway head from Portal A;
4. path crosses the arch through real graph angles;
5. on arrival, begin constructing **Portal B**;
6. Portal B becomes the new focus;
7. Portal A fades after a delayed handoff;
8. autonomous pixels continue living throughout, but do not form a packet;
9. later phases can return to strict symmetry or another generative grammar.
